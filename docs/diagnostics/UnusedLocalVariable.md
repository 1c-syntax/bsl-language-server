# Неиспользуемая локальная переменная (UnusedLocalVariable)

<!-- Блоки выше заполняются автоматически, не трогать -->
## Описание диагностики

Правило указывает имя переменной, для которой не найдено чтение. Оно учитывает аргумент вызова, возврат, индексирование и обращение к свойству или методу через переменную. Повторное присваивание само по себе не использует прежнее значение. Если переменную уже читали, правило не ищет последнее лишнее присваивание и не проверяет порядок инициализации.

Правило пропускает переменную, которой напрямую присваивают результат глобальной функции `Вычислить` (`Eval`). Функция вычисляет выражение и может вызвать исключение даже тогда, когда её результат не нужен. Отдельным оператором её вызвать нельзя.

В модулях форм, объектов и наборов записей проверяются локальные переменные процедур и функций. Переменные уровня модуля могут использоваться извне, в том числе через привязки формы. Параметры методов проверяет [UnusedParameters](UnusedParameters.md).

* В контекстном методе формы доступны её реквизиты и свойства. В методах с директивами `&НаСервереБезКонтекста` и `&НаКлиентеНаСервереБезКонтекста` присваивание по простому имени может создать локальную переменную с тем же именем, что у реквизита, свойства или переменной модуля формы.
* В модуле объекта правило учитывает реквизиты владельца, его стандартные свойства и табличные части. В модуле набора записей доступны свойства самого набора. Измерения, ресурсы и реквизиты строки доступны через запись.
* Явная локальная переменная (`Перем`) может затенять реквизит. Чтение `Форма.Имя` или `Запись.Имя` не использует отдельную локальную переменную `Имя`.
* Числовой цикл сам читает свой счётчик, в том числе если переменная объявлена или получила значение до цикла. Переменная элемента `Для Каждого` проверяется на чтение в методе.

Для разрешения простого имени в контекстном методе нужны метаданные владельца из выгрузки конфигуратора или проекта EDT и справка выбранной платформы. Для формы нужно также описание её содержимого. При неполных входных данных правило проверяет случаи, где локальная область однозначна, например явное объявление или присваивание в бесконтекстном методе формы. Тип присвоенного значения может быть неизвестен.

В неполной выгрузке правило сверяет каталог вида объекта и расположение файла модуля. У отдельных BSL-файлов вне структуры выгрузки сохраняется обычная проверка модулей неизвестного типа.

## Пример

```bsl
Процедура Тест()
    Значение = 1; // Диагностика на имени Значение.
КонецПроцедуры

Процедура Использовать()
    Значение = 1;
    Сообщить(значение);
КонецПроцедуры

Процедура ПроверитьВыражение(Выражение)
    Результат = Вычислить(Выражение); // Диагностика не срабатывает.
КонецПроцедуры
```

## Настройка

Правило включено по умолчанию в режиме `ON`. В `ONLY` его необходимо включить явно, в `EXCEPT` оно работает, пока не указано в исключениях. `ALL` включает все правила, `OFF` отключает все. Границы проверки одинаковы для всех режимов.
